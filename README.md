# Weather Analytics & Stormy

**Weather monitoring and analytics service powered by Open-Meteo**

Учебный Python-проект по инженерии и анализу метеорологических данных. Сервис объединяет ETL-процесс, базу данных PostgreSQL, интерактивный аналитический дашборд Streamlit и Telegram-бота Stormy.

Проект разработан для сбора, обработки, хранения и визуализации исторических погодных данных и прогнозов для городов мира.

## 1. Возможности проекта

### ETL-процесс

- Получение исторических и прогнозных данных через Open-Meteo API.
- Загрузка городов из CSV-справочника с проверкой координат и часовых поясов.
- Преобразование ответов API в структуру данных PostgreSQL.
- Проверка полноты исторических данных.
- Сохранение суточных и почасовых метеорологических показателей.
- Сохранение прогнозных снимков, включая дополнительные показатели ECMWF.
- Возобновление исторической загрузки с учётом последней сохранённой даты.
- Обработка ошибок отдельно для каждого города и каждого типа загрузки.
- Логирование выполнения ETL.

### Streamlit Dashboard

Интерактивный веб-интерфейс с поддержкой русского и английского языков.

Дашборд содержит три основные вкладки:

**Историческая погода (History)**

Просмотр исторических погодных показателей, суточной и почасовой динамики, дополнительных метеорологических характеристик и графиков.

**Прогноз погоды (Forecast)**

Визуализация прогнозных показателей, температуры, осадков и других доступных метеорологических параметров.

**Сравнение городов (Comparison)**

Сопоставление погодных показателей между выбранными городами.

Данные загружаются из PostgreSQL. Для сокращения повторных запросов используется кэширование Streamlit.

### Telegram-бот Stormy

Telegram-бот предоставляет погодную информацию через диалоговый интерфейс.

Возможности:

- Обработка текстовых запросов о погоде.
- Поиск и выбор городов.
- Работа с датами и периодами.
- Получение текущей и прогнозной погодной информации.
- Обработка запросов на русском языке.
- Выбор русского или английского языка интерфейса.
- Использование интерактивных кнопок.
- Сохранение пользовательского состояния через `PicklePersistence`.

Бот работает через Telegram long polling.

## 3. Архитектура

Проект организован по модульному принципу с разделением получения данных, преобразования, хранения и пользовательских интерфейсов.

```text
                 Open-Meteo API
                       |
                 HTTPX API Client
                       |
                 WeatherExtractor
                       |
                 WeatherTransformer
                       |
             Validation / Data Checks
                       |
                  WeatherLoader
                       |
                   PostgreSQL
                       |
          +------------+------------+
          |                         |
    Streamlit Dashboard       ETL Data Storage
```

Telegram-бот использует собственные компоненты обработки пользовательских запросов и получения погодных данных.

### Основные компоненты

**API Layer**

Модули `api/` отвечают за HTTP-запросы к Open-Meteo, геокодирование и получение погодной информации.

**ETL Layer**

Модули `etl/` реализуют загрузку городов, извлечение данных, преобразование, проверку и сохранение результатов.

**Database Layer**

Модули `db/` содержат описание структуры PostgreSQL и инструменты инициализации базы.

**Dashboard Layer**

Модули `dashboard/` отвечают за SQL-запросы, подготовку данных, построение графиков и отображение интерфейса.

**Bot Layer**

Модули `bot/` реализуют Telegram-интерфейс, обработку сообщений, поиск городов, интерпретацию запросов и форматирование погодных ответов.

## 5. Источники данных

Основной источник — [Open-Meteo](https://open-meteo.com/).

В проекте используются следующие категории API:

| API | Назначение |
|---|---|
| Geocoding API | Поиск городов |
| Forecast API | Текущие и прогнозные данные |
| Historical Archive API | Исторические погодные данные |
| ECMWF API | Дополнительные прогнозные показатели |

Доступные показатели зависят от конкретного API, погодной модели, географической точки и периода.

### Лицензия и использование данных

При использовании данных Open-Meteo необходимо соблюдать актуальные условия поставщика, включая требования к атрибуции и ограничения соответствующего тарифного плана.

Источник данных: [Open-Meteo](https://open-meteo.com/).

Для публичного или коммерческого использования необходимо отдельно проверить применимые условия API и лицензирования.

## 9. PostgreSQL и миграции

Проект использует PostgreSQL для хранения городов, исторических данных, прогнозов и информации о загрузках.

Структура базы описана в SQL-файле:

```text
sql/migrations/001_initial_schema.sql
```

Управление версиями схемы выполняется через Alembic.

### Первичная инициализация

При запуске ETL компонент `DatabaseInitializer`:

1. Проверяет существование базы PostgreSQL.
2. Создаёт базу, если она отсутствует.
3. Проверяет состояние схемы.
4. Создаёт начальную схему для пустой базы.
5. Регистрирует базовую ревизию Alembic.
6. Применяет доступные миграции.

Для автоматического создания базы пользователь PostgreSQL должен иметь соответствующие права.

Если в существующей базе обнаружены таблицы без истории Alembic, автоматическая регистрация baseline блокируется во избежание некорректной миграции.

### Применение миграций

Для уже подготовленной базы:

```bash
alembic upgrade head
```

История миграций хранится в `alembic/versions/`.

## 10. Запуск ETL

Точка входа:

```bash
python main.py
```

ETL выполняет следующие этапы:

1. Инициализация PostgreSQL.
2. Загрузка справочника городов.
3. Получение исторических данных.
4. Преобразование и проверка записей.
5. Сохранение исторических данных.
6. Получение прогнозных данных.
7. Сохранение прогнозных снимков.
8. Логирование результатов.

### Текущий режим запуска

В текущей версии `WeatherETL.run()` имеет следующие параметры по умолчанию:

```python
city_limit = 3
start_date = date(2026, 10, 1)
end_date = date(2026, 10, 2)
```

Таким образом, запуск через `main.py` предназначен для ограниченной загрузки.

Для полноценной регулярной обработки всех городов и расширенного исторического периода требуется отдельная настройка параметров запуска и расписания.

### Повторные загрузки

Исторический ETL учитывает последнюю успешно загруженную дату и может продолжать загрузку с последующего периода.

Ошибки отдельного города или типа загрузки регистрируются в логах, не останавливая автоматически обработку всех остальных городов.

```bash
python -m streamlit run dashboard.py
```

После запуска Streamlit выводит локальный адрес приложения в терминал.

### Интерфейс

Доступны:

- переключение русского и английского языков;
- выбор города;
- исторические погодные графики;
- прогнозные графики;
- сравнение городов.

Дашборд использует PostgreSQL как основной источник данных. Для отображения информации база должна быть доступна и содержать загруженные записи.

### Публичное развёртывание

Для размещения на Streamlit Community Cloud необходимо:

1. Разместить код в GitHub.
2. Подключить репозиторий к Streamlit Community Cloud.
3. Указать `dashboard.py` как главный файл.
4. Настроить переменные окружения и секреты.
5. Обеспечить безопасное сетевое подключение к PostgreSQL.
6. Проверить доступность приложения после развёртывания.

Публикация Streamlit не запускает автоматически ETL или Telegram-бота.

Запуск всех тестов:

```bash

```

Краткий вывод:

```bash
python -m pytest -q
```

Тесты охватывают:

- API-клиент Open-Meteo;
- чтение справочника городов;
- работу с датами;
- извлечение погодных данных;

- проверку полноты данных;

## 15. Особенности реализации

### Модульная архитектура

Логика ETL, взаимодействие с API, работа с базой и пользовательские интерфейсы разделены по пакетам.

### Валидация данных

Справочник городов проверяется на наличие обязательных полей, корректность координат, часовых поясов и повторяющихся записей.

### Работа с часовыми поясами

Проект учитывает временные зоны городов и преобразование временных меток, включая особенности переходов между летним и зимним временем.

### Обработка ошибок

ETL предусматривает отдельную обработку ошибок исторической и прогнозной загрузки.

### Локализация

Интерфейсы используют русские и английские тексты. Дополнительные переводы городов и стран хранятся в JSON-файлах.

## 16. Текущие ограничения

- Публичный Streamlit требует доступного PostgreSQL.
